# Session Log

## Rule Authority

Chronological logging behavior and checkpoint contents are owned by `../Rule/SESSION_LOG_AND_HISTORY.md`. Append-first preservation and correction behavior are owned by `../Rule/STATE_OWNERSHIP_AND_PERSISTENCE.md`. Fresh-campaign isolation is owned by `../Rule/CANON_HISTORY_AND_CAMPAIGN_ISOLATION.md`.

This file stores the campaign's completed chronological history. The labeled templates below explain how to add real entries to this campaign's copy. They are guidance only and are not themselves completed checkpoints.

## Checkpoints

During `save_revision: 0` character creation, do not add intermediate save checkpoints here. Character creation and backstory remain one evolving pre-game baseline.

When character creation is fully complete and the player confirms the transition to the Campaign Turn 1 starting baseline, add one revision-1 completion entry using the format below.

### Character Creation Completion Entry Template

- **Type:** Character creation complete / Campaign Turn 1 starting baseline
- **Save revision:** 1
- **Campaign Turn:** Not started; `campaign_turn_number` remains 0
- **Summary:** Compactly record the completed starting character/backstory state and any continuity-critical setup facts needed to understand the campaign baseline.
- **Notes:** Include only established facts. Do not reproduce every blank field, rejected option, or discussion detail.

After gameplay begins, append one entry for each completed and permanently saved Campaign Turn.
